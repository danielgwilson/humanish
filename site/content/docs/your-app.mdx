---
title: Study your own app
description: Point a synthetic participant at your preview URL, a repository built inside the desktop, or the app running on your machine.
---

You have a build nobody outside the team has used, and you want to know where a newcomer gets stuck. Give one participant one concrete job, let them try it, and keep what came back for the next change.

Use an app you own or have permission to study, with synthetic accounts and data. Pick the route that matches where your app runs:

- **A preview or staging URL:** the hosted route below. This is the common case.
- **A repository, not yet deployed:** the [clone route](#build-the-app-inside-the-sandbox) builds it inside the desktop.
- **Running on your machine, and you use Codex:** the [local-browser route](#study-your-running-local-app) needs no E2B or OpenAI key.

## Create a lab for your preview URL

Finish the [install and keys](/docs#add-two-keys), including `@e2b/desktop`. Then create `.humanish/labs/your-app.yaml`. That directory is ignored by git, which makes it the right place for preview URLs and experiments. Replace the URL and the task with yours:

```yaml title=".humanish/labs/your-app.yaml"
schema: humanish.lab.v2
id: your-app
title: First project, a newcomer
subject:
  source: app-url
  appUrl: https://preview.example.com/
actors:
  - type: openai-computer-use
    persona: synthetic-new-user
    count: 1
    maxOutputTokens: 8192
    mission: >-
      You are trying this project-management app for the first time.
      Create a project named Weekend plan, then find it again and
      rename it Saturday plan. Stop when you finish or get stuck.
      Say what happened and what confused you.
execution:
  target: e2b-desktop
  timeoutMs: 600000
  caps:
    maxTotalUsd: 4
    maxUsd: 2
scenario:
  mode: live
policies:
  allowPublicTargets: true
defaults:
  open: true
```

Write the task the way you would brief a person. "Create a project and find it again" leaves room for the participant to look around. "Click the plus icon in the top right" hands them the answer and hides the navigation problem you wanted to see.

The two caps are checked on every run and do not carry across runs: `maxTotalUsd` is the study's model budget, `maxUsd` the backstop per participant. Desktop time is billed on top, and a supported live run also requests analysis when it finishes, which is refused when its estimate exceeds $3. [Budgets](/docs/budgets-and-privacy#set-a-study-budget) has the exact rules and the opt-outs.

To use your signed-in Codex or Claude Code as the participant instead of the OpenAI key, swap the actor for the [local-agent fragment](/docs/local-agents); that route skips analysis unless an OpenAI key is present.

One public URL takes one participant per run on this route. For a second observation, reset the test data or use another test account and run the lab again, and keep both run ids so the first is not lost behind `latest`. For several newcomers at once, each on their own copy of the app, use the clone route below.

## Check, then run

These two commands create no desktop and call no model:

```bash
npx humanish lab inspect .humanish/labs/your-app.yaml
npx humanish doctor --lab .humanish/labs/your-app.yaml
```

`lab inspect` prints the resolved lab, including the persona text the participant will get. `doctor` tells the participant's authentication apart from desktop access and analysis; it does not check keys against the provider or confirm quota. With `--env-file <path>`, pass it to both `doctor` and the run command.

Next, check that a hosted desktop can reach the preview. This needs `E2B_API_KEY`, creates one desktop for the probe and shuts it down afterwards, and makes no model call:

```bash
npx humanish lab preflight .humanish/labs/your-app.yaml --reachability public-preview
```

The probe only confirms reachability from E2B; it does not log in through preview protection. Make the deployment reachable, then run:

```bash
npx humanish run .humanish/labs/your-app.yaml
npx humanish observe --run latest --open
```

To watch the desktop during the study, use `watch` in place of `run`. For an agent or a CI job, add `--json`. [Read results](/docs/read-results) before changing the app or adding participants.

## Build the app inside the sandbox

A deployment is optional. The starter `humanish/labs/cua-browser.yaml` shows the pattern: clone a repository, install, build and start the app inside each desktop. Replace the `subject` block with your repository and its real commands:

```yaml
subject:
  source: clone
  repos: [your-org/your-app]
  serve:
    install: npm ci
    build: npm run build
    start: npm run start -- --hostname 127.0.0.1 --port 3000
    url: http://127.0.0.1:3000/
```

The start command shown fits a Next.js app; use yours, with a readiness URL on the port it serves. Remove `policies.allowPublicTargets`: the app is served inside the desktop, and a clone lab that keeps it is refused at parse when `count` is above 1. For two participants, set `actors[0].count` to `2`: each gets its own clone and desktop under the same `$4` study budget. A shared external database still needs separate test accounts or data.

If you edit the scaffolded `cua-browser.yaml` directly, change `scenario.mode` from `dry-run` to `live` and add a budget; a dry run produces contract evidence, not a study of the app.

For uncommitted code, `subject.source: local-tree` packages a selected working tree with a content pin. Environment allowlists, state seeding and the other subject routes are in the [computer-use reference](/docs/computer-use#choose-a-subject) and the [schema contract](https://github.com/danielgwilson/humanish/blob/main/docs/contracts/schemas.md).

## Study your running local app

This route drives a browser on your own machine through your signed-in Codex account, so it needs neither E2B nor an OpenAI API key. It needs a supported Codex CLI with a file-backed ChatGPT login, plus either Linux x64 with rootful Docker Engine, KVM and TUN, or an M3-or-newer Mac with native ARM64 Node and Lima 2.2 or later. Docker Desktop is not supported. Check the [account profile](https://github.com/danielgwilson/humanish/blob/main/docs/architecture/restricted-codex-analysis.md) and [platform setup](https://github.com/danielgwilson/humanish/blob/main/docs/architecture/local-browser-runtime.md) first.

Start your app, then replace the URL and the task:

```bash
npm install --save-dev humanish
npx humanish init --yes \
  --local-browser http://127.0.0.1:3000 \
  --local-mission "Create a project named Weekend plan, find it again, and rename it Saturday plan. Stop when you finish or get stuck, and explain anything confusing."
npx humanish doctor --lab local-browser
npx humanish run local-browser
```

If you already ran `init`, edit `subject.appUrl` and the actor's `mission` in `humanish/labs/local-browser.yaml` instead; `init` keeps existing files and warns that these options were skipped. Use an explicit loopback port above 1023.

The starter gives one participant two minutes. For a longer task, raise `execution.timeoutMs` in the lab before running. `doctor` checks setup without launching a participant or downloading the runtime; the first live run prepares the pinned browser image and later runs reuse it. The participant and the separate analyst both use your Codex plan and remote inference, so the dollar cost is unknown rather than zero. This route does not fall back to a hosted desktop if setup fails.

```bash
npx humanish observe --run latest --open
# In another terminal while Observer is open:
npx humanish verify --run latest --json
```

For signup flows, point your test app's outgoing mail at the [local captured inbox](https://github.com/danielgwilson/humanish/blob/main/docs/architecture/comms-inbox.md#local-browser-studies). It accepts HTTP mail or optional SMTP and never receives mail sent to a real mailbox.

## Give the participant a background

`humanish init` writes editable profiles under `humanish/personas/`. Set the actor's `persona` to a profile's id. A profile can be a few sentences or a longer account of who this person is:

```yaml title="humanish/personas/volunteer-organizer.yaml"
schema: humanish.persona.v1
id: volunteer-organizer
name: Morgan
summary: A volunteer organizer trying an unfamiliar planning app.
background: |
  Morgan coordinates twelve volunteers using spreadsheets and email.
  They know those tools well but have never used this product.
  They spend Sunday evening reconciling replies and worry about
  making the roster public or losing their own copy.
```

The background is who they are; the mission is what they are doing today. Give enough context for the participant to make choices, and keep the expected defect and the hidden completion rule out of both.

Backgrounds keep their paragraphs up to 32 KiB of UTF-8; a larger or invalid background stops the run before it starts. `summary` is limited to 280 characters and is shortened with a warning. Missing files and unsupported fields warn; `backstory` is not an alias. Trait directives such as `keyboard_first` (a preference that allows pointer fallback) and `keyboard_only` (a condition that does not) are instructions to the participant, not enforced restrictions, and do not certify accessibility.

Inspect the resolved persona text before spending on a study:

```bash
npx humanish lab inspect .humanish/labs/your-app.yaml --json
```

The `personas` field shows the authored context, separate from the task, route instructions and runtime additions such as inbox access. The bundle records what was supplied; it cannot prove the participant followed it. Keep profiles synthetic or de-identified and review them before committing or sharing; pattern redaction cannot certify that a personal story is safe to publish.

## Make a useful comparison

Keep the task, personas, app state and model settings the same between runs, and record the app revision before and after. Look for the specific friction to disappear, then check whether something new replaced it.

Report denominators: "2 of 2 completed; 1 reported friction." A run finishing, a participant saying it succeeded, and independent task evidence are three different observations; [Read results](/docs/read-results) explains how to read them together. Two participants can show repeatable friction; they cannot establish population-wide usability.

Move a lab into committed `humanish/labs/` only when its URLs, personas, tasks and examples are safe to publish. Generated evidence stays in `.humanish/`.
