---
title: Study your own app
description: Study your running local app with a Codex account, or use a hosted desktop for a preview URL.
---

You have a preview build and want to know where a newcomer gets stuck. Give participants one concrete job, let them try it, and keep the evidence for the next change.

Use an app you own or have permission to study, with synthetic accounts and data. Choose the route that fits where your app runs:

- **Local app and Codex account:** use the commands below. No E2B or OpenAI API key is required.
- **Public preview or staging URL:** use the [hosted lab](#create-a-lab-for-your-preview-url).
- **App built inside a sandbox:** use the [clone route](#build-the-app-inside-the-sandbox).

## Study your running local app

Install `humanish` with Node.js 20+ in your project. This route needs a supported
Codex CLI with a file-backed ChatGPT login. Linux x64 needs a local rootful Docker
Engine, KVM and TUN; M3-or-newer Macs need native ARM64 Node and Lima 2.2+.
Check the [qualified account profile](https://github.com/danielgwilson/humanish/blob/main/docs/architecture/restricted-codex-analysis.md)
and [platform setup](https://github.com/danielgwilson/humanish/blob/main/docs/architecture/local-browser-runtime.md)
before running. Docker Desktop is not the supported runtime for this route.

Start your app, then replace the loopback URL and task with yours. If you already
ran `init`, edit `subject.appUrl` and the actor's `mission` in
`humanish/labs/local-browser.yaml` before running: initialization preserves
existing files and warns when these options are skipped.

```bash
npm install --save-dev humanish
npx humanish init --yes \
  --local-browser http://127.0.0.1:3000 \
  --local-mission "Create a project named Weekend plan, find it again, and rename it Saturday plan. Stop when you finish or get stuck, and explain anything confusing."
npx humanish doctor --lab local-browser
npx humanish run local-browser
```

The starter creates one participant with a two-minute task budget. For a longer
journey, edit `execution.timeoutMs` in `humanish/labs/local-browser.yaml` before
running, up to 1,200,000 ms (20 minutes). Use an explicit loopback port above 1023.

`doctor` checks setup without launching a participant or downloading the runtime.
The first live run prepares the pinned browser image; later runs reuse it.
Participants and the separate automatic analyst use your Codex account quota
and remote model inference. Dollar cost is unknown, not zero. This local route
does not need `@e2b/desktop`; it does not fall back to a hosted desktop if setup
fails.

Open the result and check its evidence:

```bash
npx humanish observe --run latest --open
# In another terminal while Observer is open:
npx humanish verify --run latest --json
```

For signup flows, configure your test app to send email to the
[local captured inbox](https://github.com/danielgwilson/humanish/blob/main/docs/architecture/comms-inbox.md#local-browser-studies).
The catch accepts HTTP mail or optional SMTP; it does not receive mail sent to a
real external mailbox. Review [outcomes and sharing limits](/docs/read-results)
before acting on or sharing the report.

## Create a lab for your preview URL

For hosted desktops, finish the [API provider setup](/docs#connect-a-desktop-and-a-model),
including the `@e2b/desktop` peer.

Create `.humanish/labs/your-app.yaml`. This ignored directory is a good place for local preview URLs and experiments. Replace the example URL and mission with your app and a task it actually supports.

```yaml title=".humanish/labs/your-app.yaml"
schema: humanish.lab.v2
id: your-app
title: First project, a newcomer
subject:
  source: app-url
  appUrl: https://preview.example.com/
actors:
  - type: openai-computer-use
    persona: synthetic-new-user
    count: 1
    mission: >-
      You are trying this project-management app for the first time.
      Create a project named Weekend plan, then find it again and
      rename it Saturday plan. Stop when you finish or get stuck.
      Say what happened and what confused you.
execution:
  target: e2b-desktop
  timeoutMs: 600000
  caps:
    maxTotalUsd: 4
    maxUsd: 2
scenario:
  mode: live
policies:
  allowPublicTargets: true
defaults:
  open: true
```

This sends one participant into your deployed app. For a second observation, reset the test data or use a separate test account, then run the lab again. Keep both run IDs so the first result is not lost behind `latest`.

This hosted example uses `OPENAI_API_KEY` for the participant and `E2B_API_KEY` for the desktop. To use your Codex or Claude Code login for the participant on E2B, replace the actor with the [local-agent fragment](/docs/local-agents). That hosted route defaults to OpenAI API analysis, skipped without its key. The local-browser route above defaults to a separate Codex account analyst.

On this hosted route, a single public URL is limited to one participant per independent-world run. A simultaneous multi-user study needs the explicit shared-world route. To give multiple newcomers separate copies of the app, use the clone route below.

The `$4` participant-model budget and `$2` per-participant backstop are checked for each run; budgets do not carry across separate invocations. E2B desktop time is additional. Supported live studies also run analysis on completion by default, with a separate `$3` analysis budget. See [budget limits](/docs/budgets-and-privacy#set-a-study-budget) for caps and opt-outs.

Keep the mission in the participant's language. “Create a project and find it again” leaves room for discovery. “Click the plus icon in the top right” tells the participant the answer and hides the navigation problem you wanted to study.

## Check, then run

Inspect the lab, then check the selected route's local setup. These commands create no desktop and make no model request:

```bash
npx humanish lab inspect .humanish/labs/your-app.yaml
npx humanish doctor --lab .humanish/labs/your-app.yaml
```

`doctor` distinguishes the participant's authentication from desktop access and post-run analysis. It does not validate provider credentials remotely or confirm model access and quota. When using `--env-file <path>`, pass it to both `doctor` and the run command.

Next, check whether a hosted desktop can reach the preview. This requires `E2B_API_KEY`, creates one E2B desktop and incurs desktop time. It makes no model calls and shuts down the probe desktop afterwards:

```bash
npx humanish lab preflight .humanish/labs/your-app.yaml --reachability public-preview
```

The probe checks reachability from E2B. It does not authenticate through preview protection or verify the app's behavior. Make the test deployment accessible before starting the study:

```bash
npx humanish run .humanish/labs/your-app.yaml
npx humanish observe --run latest --open
```

To watch the desktop during the study, use this instead of `run`:

```bash
npx humanish watch .humanish/labs/your-app.yaml
```

For an agent or CI job, use `run ... --json`. [Read the result](/docs/read-results) before changing the app or expanding the panel.

## Build the app inside the sandbox

A public deployment is optional. The starter `humanish/labs/cua-browser.yaml` shows how to clone a repository, install dependencies, build, and start the app inside each sandbox.

Replace the `subject` block in your lab with your public repository and its real commands:

```yaml
subject:
  source: clone
  repos: [your-org/your-app]
  serve:
    install: npm ci
    build: npm run build
    start: npm run start -- --hostname 127.0.0.1 --port 3000
    url: http://127.0.0.1:3000/
```

The example start command fits a Next.js app. Use the command your project supports and a readiness URL on its actual port. Remove `policies.allowPublicTargets` when the app is served only on sandbox loopback. For a two-participant panel, change `actors[0].count` to `2`: each participant now gets its own clone and desktop, with the existing `$4` shared model budget. Shared external databases still need isolated test accounts or data.

Two participants can reveal repeatable friction; they cannot establish population-wide usability.

When editing the scaffolded `cua-browser.yaml` directly, also change `scenario.mode` from `dry-run` to `live` and add your study budget. Leaving it in dry-run produces contract evidence, not a real app study.

For uncommitted code, `subject.source: local-tree` can package a selected working tree with a content pin. For environment allowlists, state seeding, local-tree configuration, and other subject routes, use the [source guide](/docs/computer-use#choose-a-subject) and [lab schema and parser](https://github.com/danielgwilson/humanish/blob/main/src/lab-config.ts).

## Make a useful comparison

Keep the task, personas, app state, and model settings stable between runs. Record the before and after app revisions. Look for the specific friction to disappear, then inspect whether a new one replaced it.

Report denominators: “2 of 2 completed; 1 reported friction.” A run finishing, a participant claiming success, and independent task evidence are different observations. The [results guide](/docs/read-results) explains how to read them together.

Move a lab into committed `humanish/labs/` only when its URLs, personas, tasks, and examples are safe to publish. Leave generated evidence in `.humanish/`.
