# 0.101.0 — Shared Codex UI tools

Codex participants now interact through a native Humanish UI tool. One continuing
Codex conversation can call the tool repeatedly, inspect each new screenshot,
and give its final feedback. Humanish executes and records the inputs, including
rejected or skipped actions, before returning their actual status to Codex.

Local Firecracker and hosted E2B Codex participants use the same implementation.
The duplicate hosted adapter is removed. Hosted studies retain their operator
login, configured model selection and explicit reasoning effort; local account
studies retain their qualified isolated login profile. Codex runs on the host,
with desktop inputs sent to the selected sandbox. No credentials are moved into
the desktop and no new Firecracker image is required.

The native integration uses Codex CLI **0.154.0** and its experimental dynamic
tool protocol. Other CLI versions fail with an unsupported-version diagnostic.
Update to the supported version when moving a hosted study from an older CLI.

The existing loop still owns recordings, action limits, stop conditions and
cancellation. Pending tool calls are not counted as finished model requests.
Known pending usage informs spend estimates; final usage is recorded once when
the native turn settles. Interrupted or compacted requests retain explicit usage
uncertainty. Account inference has unknown dollar cost.

Automatic analysis remains a separate, restricted analyst. The OpenAI Responses
computer-use provider and Claude Code conversation adapter remain supported.
Older recordings remain readable in Observer.
