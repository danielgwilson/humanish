# Humanish 0.87.0: see why a participant stopped

The Observer now distinguishes a provider response limit from elapsed time or
estimated spend. Participant cards, summaries and reports show the recorded
cause, including for participants with no screenshot frames. New computer-use
traces retain an optional `stopCause` alongside the existing status and
completion reason.

New computer-use sessions that hit their estimated spend cap before any action
are classified as interrupted, with no target-app feedback inferred from that
harness stop. The cap timing and recorded usage are unchanged.

Older recordings use exact machine-generated notices where available. A recorded
“provider token limit reached” notice remains **provider token limit**: it does
not establish whether the provider exhausted its output or context allowance.
When an older run records only a generic limit, the Observer says **limit
reached**. Updating a viewer preserves the original evidence and outcome counts;
it does not infer a cause from participant prose.

On phones, a saved landscape capture in Fit mode keeps playback controls beside
the fitted image. Portrait captures, zoomed views and live views retain their
bounded viewing area. The run banner states **Saved recording** once; the player
keeps the participant status and selected capture timestamp. Exact action links
and saved-moment recall retain their existing behavior.

Expanded assignments show the recorded lane focus before the mission, so a long
mission does not put those instructions below it in the phone panel. The full
mission and participant tasks remain available.

The website also explains credential placement by execution route. Computer-use
model keys remain on the host. Terminal actors receive a command-scoped runtime
key by default; optional `openai-egress` keeps the raw key outside the sandbox
while still allowing sandbox processes to make paid requests through its proxy.
Evidence stays local by default, and exposing Observer or sharing an export makes
it accessible to others. See the [credential and sharing guide](https://humanish.dev/docs/budgets-and-privacy#store-credentials).

Install with `npm install -g humanish@0.87.0`. Reopen a run with
`humanish observe --run RUN`, or regenerate its HTML export, to use the updated
viewer. Existing HTML files retain the renderer that produced them.

## Verification and limits

[Interruption-cause checks](https://github.com/danielgwilson/humanish/pull/747)
cover recorded provider output limits, legacy token-limit notices, elapsed time,
spend and incomplete provider responses. Tests preserve old outcome counts and
source evidence through served and exported projections. A retained real
recording was inspected at desktop and phone widths, including its participant
whose provider stopped before any app action.

[Zero-action spend-cap checks](https://github.com/danielgwilson/humanish/pull/752)
verify one provider turn, zero executed actions, retained usage, an interrupted
outcome and no inferred target-app feedback. Older bundle counts are unchanged.

[Phone review checks](https://github.com/danielgwilson/humanish/pull/746) cover
landscape and portrait capture/control spacing, keyboard seeking, focus, zoom,
action links, refresh and saved-moment recall against retained recordings.
These browser checks do not establish physical-phone behavior or new live-stream
coverage. Screenshot replay remains sparse, and no participant success rate or
incremental persona benefit is inferred from these changes.

The [assignment ordering change](https://github.com/danielgwilson/humanish/pull/754)
preserves recorded text while moving lane instructions to the top of expanded
assignments. This addresses visibility; it does not establish that every reader
will interpret the instructions correctly.
