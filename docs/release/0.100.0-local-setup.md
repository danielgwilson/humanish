# 0.100.0 — Local study setup and startup reliability

Initialize a local browser study for your app without writing its lab manifest:

```sh
humanish init --yes --local-browser http://127.0.0.1:3000 \
  --local-mission "Create a note and find it again"
humanish doctor --lab local-browser
humanish run local-browser
```

The starter uses local Firecracker browsers and the supported Codex account
login. Model inference remains remote and consumes account quota; E2B and OpenAI
API keys are unnecessary for this route. Linux needs local Docker/KVM/TUN;
supported Apple Silicon Macs use Lima. Init and the TUI explain prerequisites
and reuse the CLI's readiness checks. Existing lab files are preserved; if the
local starter already exists, edit its URL and mission in
`humanish/labs/local-browser.yaml` instead of rerunning the init flags.
The free preview and hosted starter remain available. Local dry runs work without
starting a desktop or requesting a model turn.

The first local participant capture now follows the target document's
DOMContentLoaded event and a paint. Previously a fixed 500 ms wait could expose
the runtime's starter page. Navigation is bounded, supports redirects, and
reports startup failures; it does not wait for all app data or subsequent loads.
Updated x64 and ARM64 runtime images carry the initial-navigation change.

Failed account participant requests retain their finite execution stage, such
as `thread/start`, in the recording and outcome text. Older recordings remain
readable. This adds diagnostic evidence without changing retry or deadline
behavior; it does not claim the cause of a past timeout is known.
