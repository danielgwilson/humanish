# Humanish 0.88.3: native UTF-8 typing without automatic replay

Managed E2B desktops now transfer text as UTF-8 file data before one native
keyboard command. This avoids the SDK's UTF-16 chunk boundaries and uses a
command-local UTF-8 locale. Input follows the focused control's caret and
selection. Humanish does not clear the field, normalize the text or assign
its DOM value.

A failed write can leave partial input. Humanish now stops that participant
with an input-uncertain error instead of replaying the whole payload through
the clipboard. Missing completion status and native diagnostic output also
stop the action; a zero exit alone is insufficient. Raw typed text and command
errors are omitted from the public error notice. Temporary-file cleanup is
reported separately, with unknown transfer completion kept uncertain.

Native actions accept up to 2,048 Unicode scalar values and retain the 75ms
keyboard delay. NUL, malformed UTF-16 and larger inputs are rejected before
typing; empty input is a no-op. The native process has a 180-second GNU timeout
and a one-second forced-stop grace period. Images need xdotool, GNU timeout
and `C.UTF-8`. This adds a per-action compatibility limit; longer text needs
explicit separate actions.

Aborting closes further input dispatch after preparation. It cannot prove
that an already admitted keyboard process stopped immediately. Native runtime
limits and owned sandbox cleanup still apply. Pending or uncertain typing
blocks later input through another executor on that desktop. Sequential shared
studies also stop window changes and later participants, preserving the original
participant outcome and recording the shared-desktop error separately.

Newlines, tabs, input methods, keyboard layouts and app event handlers can
affect what a control accepts;
this is not a guarantee of arbitrary Unicode support.

Custom desktop ports keep their successful `write(text)` implementation unless
they opt into native typing. Their uncertain failures also stop without replay.
The former `CuaTypeFallbackError` export remains for compatibility.

The CLI also explains why an empty feedback candidate list can still produce
a saved-summary draft. Listing candidates does not create a finding or verify
share safety. Candidate selection, JSON, draft Markdown and sharing gates
retain their existing behavior.
