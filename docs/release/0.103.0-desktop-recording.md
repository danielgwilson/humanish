# 0.103.0 — Optional desktop video and audio

Computer-use studies can retain an MP4 alongside screenshots, actions,
participant feedback and analysis:

```yaml
execution:
  desktop:
    recording: { audio: true }
```

Set `audio: false` for screen-only video. Omit `recording` for the existing
lightweight captures. Recording does not enable camera or speech features.

Observer plays the selected participant's video on the existing study timeline.
Opening a participant, scrubbing and returning to the grid preserve the cursor.
Audio starts muted; the selected participant has an explicit audio control.
Unavailable video falls back to screenshots where they exist.

Local Firecracker and hosted E2B use the same capture settings and evidence
format. Local capture uses the optional media runtime archive. Recorder failure
preserves the study; a playable interrupted or size-limited recording is marked
partial. The per-participant file limit is 128 MiB.

Continuous media stays local-only. Screenshot redaction does not redact video
or audio. Portable HTML exports explicitly omit continuous media; analysis
continues to inspect screenshots and text. See the
[recording guide](../architecture/desktop-recording.md) for supported routes,
capture semantics and export behavior.
