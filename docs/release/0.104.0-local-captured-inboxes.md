# 0.104.0 — Local captured inboxes

Local browser participants can now create an account, open their assigned inbox
and follow a verification link without mailbox-provider credentials. Start
`humanish comms catch`, configure the app to send email to that catch, and declare
`comms.email.external.catchBaseUrl` in the local lab. Doctor checks the catch's
recipient routes and explains setup failures before a participant starts.

Each desktop forwards only its assigned recipient's read-only inbox. Operator
mail, other recipient routes and the private delivery drain are unavailable
through that forward. The existing renderer, mission instructions, shared study
runner and digest-only comms evidence are reused. Supported inline raster images
render; unsupported images retain an explicit placeholder.

This captures the target app's outgoing mail. It does not receive arbitrary
internet email or add real-provider receiving to local-agent studies. Existing
hosted receiving and its management-credential boundary remain unchanged.

Verification includes two concurrent Linux local Codex participants with distinct
messages and independently verified app accounts, automatic analysis, supported
and unsupported image rendering, a browser-runtime isolation/cleanup check, and
real OpenSSH forwarding with controller-death cleanup. Native ARM runtime builds
exercise the same recipe; this release does not claim a new Mac end-to-end run.
Raw study screenshots remain local-only under the normal verification rules.

The capability table and older media/account/timeout issues were also reconciled
with shipped behavior. Token counts do not establish plan quota or dollar cost;
the original intermittent pre-profile timeout remains unresolved. Recording
startup gaps remain tracked separately in #854.
