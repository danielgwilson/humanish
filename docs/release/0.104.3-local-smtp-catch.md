# 0.104.3 — SMTP capture for local app studies

`humanish comms catch --smtp-port 1025` now opens the documented loopback
SMTP listener. Previously, the host CLI rejected the option even though the
shared catch already supported SMTP. Apps that send verification mail over SMTP
can use the same recipient inbox and evidence pipeline as HTTP-based apps.

The optional SMTP port must be valid and distinct from the HTTP capture and
read-only inbox ports. A busy SMTP port now stops startup before HTTP health
can report success; previously its background thread failed while HTTP stayed
healthy. SMTP remains bound to loopback, and omitting the option preserves
HTTP-only capture. No mailbox provider or runtime image change is needed.

See [the inbox setup guide](../architecture/comms-inbox.md) for app and lab
configuration. Fixes #878.
