# 0.103.1 — Fairer analysis capture allocation

Analysis now gives reclaimed screenshot slots to eligible participants with
fewer admitted images. Previously, a participant whose images exceeded its
initial byte reservation could receive only its ending capture while other
participants received extra captures, even with enough image bytes remaining.

The fix preserves the 40-capture cap, byte and read limits, source identities,
and within-session selection order. Existing recordings and analyses remain
unchanged; a new analysis uses the corrected allocation. Completion still
requires affirmative evidence for every essential assignment requirement.

A synthetic 48-capture regression reproduces the missed beginning frame, and
selection on a retained study confirms more balanced participant coverage.
These checks establish allocation behavior, not improved model interpretation
or guaranteed selection of every decisive moment. The original outcome-evidence
incident in [#851](https://github.com/danielgwilson/humanish/issues/851) remains
under investigation; this release does not claim to resolve it.
