# 0.103.2 — Adjacent ending evidence for analysis

A participant can inspect a result and then scroll or navigate before ending.
Analysis now prioritizes the preceding screenshot alongside the final view,
after beginning and explicit failure context. Previously, session sampling
could omit that nearby result while retaining a final heading or navigation page.

The 40-capture cap, byte and read limits, and completion requirements are
unchanged. Selection uses source order, not success declarations. Existing
recordings and analysis attempts remain unchanged; reanalysis creates a new
attempt using the revised selection.

In a retained two-participant case, the omitted views showed the required final
rows. Paired replays with the same current analyst prompt and transport changed
both outcomes from unknown to completed with supporting visual citations.
An authored 90-capture control retained a supported local-save success while
leaving contradicted and unverified submission claims unknown.
This addresses the observed omission in
[#851](https://github.com/danielgwilson/humanish/issues/851); it does not guarantee
selection of every decisive moment. Reports still disclose partial coverage,
and an unverified essential requirement still warrants an unknown outcome.
