# Glossary

Use one word per concept. Docs and new code use the terms in the first table. Some lab, bundle and
output fields keep older spellings; the second table maps them.

| Term         | Meaning                                                                                                                                                                                                                                                                                                                                                                            | Where it lives in the code                                                                                                                                                                                                                                                                                          |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| study        | The prose word for everything one `humanish run <lab>` produces: participants, evidence and analysis. Each study writes one run.                                                                                                                                                                                                                                                   | No type of its own; see run.                                                                                                                                                                                                                                                                                        |
| run          | One execution on disk: `.humanish/runs/<runId>/`, with `run.json` (`humanish.run-bundle.v1`) as the source of truth.                                                                                                                                                                                                                                                               | `src/run/`; `RunBundle` in `src/run/bundle.ts`                                                                                                                                                                                                                                                                      |
| lab          | A YAML manifest that declares a study: `humanish/labs/<id>.yaml`, schema `humanish.lab.v2`.                                                                                                                                                                                                                                                                                        | `src/lab/`; `LabConfig` in `src/lab/types.ts`, parsed by `parseLabConfig` in `src/lab/config.ts`                                                                                                                                                                                                                    |
| participant  | One simulated person, or agent, taking part in a study. `run.json` records each one as a `simulations[]` entry with one or more `streams[]`.                                                                                                                                                                                                                                       | No single type yet. Each route runs its own: `runCuaLane` in `src/routes/computer-use/lanes.ts`, the shared-world lanes in `src/routes/shared-world/provisioned.ts` and `src/routes/shared-world/handoff.ts`, the terminal session in `src/routes/terminal/session.ts`, fixture simulations in `src/run/dry-run.ts` |
| persona      | Who a participant is: traits, background, device. `humanish/personas/<id>.yaml`.                                                                                                                                                                                                                                                                                                   | `src/lab/persona.ts`, `src/lab/persona-resolve.ts`                                                                                                                                                                                                                                                                  |
| mission      | The free-form brief a model-driven participant receives: `actors[].mission`. `actors[].tasks[]` adds discrete tasks: each has a `goal` the participant sees and an optional `success` check it does not.                                                                                                                                                                           | `LabActor` in `src/lab/types.ts`                                                                                                                                                                                                                                                                                    |
| assignment   | What one participant was asked to do: the mission, the lane's `instruction` or `laneFocus.instruction` (recorded as `focus`), and the tasks. Each stream records it as `streams[].assignment`.                                                                                                                                                                                     | `participantAssignment` in `src/lab/participant-assignment.ts`; `RunParticipantAssignment` in `src/run/streams.ts`                                                                                                                                                                                                  |
| scenario     | Two things share the word. The lab's `scenario` block holds run settings: `mode` (`dry-run` or `live`), `caps`, and an optional `ref`. The `ref` names a scenario file, `humanish/scenarios/<id>.yaml` (`humanish.scenario.v1`): a goal and ordered steps with expectations. Only the scripted-browser route executes those steps. A model-driven participant follows its mission. | `LabScenario` in `src/lab/types.ts`; steps run in `src/routes/scripted-browser/lab.ts`                                                                                                                                                                                                                              |
| subject      | The product under study, declared by `subject.source`: `clone`, `app-url`, `local-tree`, `terminal-product`, `desktop-cli`, `local-app` or `this-repo`. `run.json` records its provenance under `subject`.                                                                                                                                                                         | `LabSubject` in `src/lab/types.ts`, parsed in `src/lab/parse/subject.ts`                                                                                                                                                                                                                                            |
| actor        | The model or program that drives a participant, declared by `actors[0].type`, e.g. `openai-computer-use`, `local-agent`, `scripted-browser`, `codex-exec`.                                                                                                                                                                                                                         | `src/actors/`; `actorRegistry` in `src/actors/registry.ts` lists every one; `ActorTrace` in `src/actors/contract.ts` is its record                                                                                                                                                                                  |
| computer use | A model drives a participant by reading screenshots of a desktop and acting with mouse and keyboard. `openai-computer-use` and `local-agent` are the computer-use actors. CUA is the short form the code and CLI output use: the backend name `cua`, the `HUMANISH_CUA_LAB_*` error codes and names such as `CuaExecutor`.                                                         | `src/routes/computer-use/`, `src/actors/computer-use/`                                                                                                                                                                                                                                                              |
| route        | The execution path for a lab: `computer-use`, `shared-world`, `scripted`, `terminal` or `preview`. `preview` writes a dry-run bundle for `this-repo` subjects with no live participant.                                                                                                                                                                                            | `routeOf` and `LabRoute` in `src/lab/plan.ts`; predicates in `src/lab/routing.ts`; one folder or file per route in `src/routes/`                                                                                                                                                                                    |
| substrate    | Where a participant's desktop or shell runs: a hosted E2B sandbox, or a local Firecracker VM (inside Lima on macOS).                                                                                                                                                                                                                                                               | `src/substrates/e2b/`, `src/substrates/local/`                                                                                                                                                                                                                                                                      |
| topology     | Whether participants share one instance of the subject. `subject.topology` is `per-lane-worlds` (the default, one each) or `shared-world` (one for all).                                                                                                                                                                                                                           | `LabSubjectTopology` in `src/lab/types.ts`                                                                                                                                                                                                                                                                          |
| stream       | One live or recorded view of a participant, such as a browser or a terminal, in `run.json` and the Observer.                                                                                                                                                                                                                                                                       | `RunStream` in `src/run/streams.ts`                                                                                                                                                                                                                                                                                 |
| Observer     | The single-file review page built from `observer/observer-data.json` (`humanish.observer-data.v1`).                                                                                                                                                                                                                                                                                | `observer/` (the page), `src/observer/` (data, render, serve)                                                                                                                                                                                                                                                       |
| evidence     | Files a run keeps: screenshots, traces, transcripts, recordings. `verify` checks them and grades share-safety.                                                                                                                                                                                                                                                                     | `src/evidence/`; `verifyRun` in `src/verify/verify.ts`                                                                                                                                                                                                                                                              |
| finding      | A result of study analysis, with citations to evidence in the run. Each finding groups the observations that support it.                                                                                                                                                                                                                                                           | `src/analysis/`                                                                                                                                                                                                                                                                                                     |
| observation  | One claim in study analysis with its basis, evidence ids and limitation. `concernReviews[]` gives each material concern's observation a disposition: `finding`, `context` or `unsupported`.                                                                                                                                                                                        | `src/analysis/`                                                                                                                                                                                                                                                                                                     |

## Read these field spellings as the concept they name

Fields documented in [docs/contracts/](docs/contracts/schemas.md), in `TELEMETRY.md` and in the
library exports of `src/index.ts` are API, so they keep their spelling. Prose and new code use the
concept word.

| Spelling                                                    | Where it appears                                                                                                                                                                                                                                                       | Concept                       |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| `lanes`, `laneFocus`, `laneId`, `laneWindows`, `laneGroups` | `actors[0].lanes[]` and `actors[0].laneFocus` in a lab; `streams[].laneId` and `sharedWorld.laneWindows` in `run.json`; `laneGroups` in Observer data                                                                                                                  | participant                   |
| `roles`, `roleId`, `roleCount`                              | `run.json` `sharedWorld`: `roleCount`, and `roleId` on `laneWindows`, `outcomes` and the older sequential records                                                                                                                                                      | participant in a shared world |
| seat                                                        | Prose only: the shared-world docs call a participant a seat. No field uses the word.                                                                                                                                                                                   | participant in a shared world |
| `simulations`, `simId`, `simCount`                          | `simulations[]` in `run.json` (one per participant), `simId` on streams and shared-world records, `simCount` in `run.json` and Observer data                                                                                                                           | participant                   |
| `streams`, `streamId`                                       | `streams[]` in `run.json`; `streamId` on shared-world records                                                                                                                                                                                                          | stream                        |
| `backend`                                                   | The `backend` field of `humanish.lab-preflight-result.v1`; `LabBackend`, `selectLabBackend` and `LabOutcome.backend` in `src/index.ts`. The values are older route names: `cua` is computer-use, `concurrent-shared-world` is shared-world and `synthetic` is preview. | route                         |
| `cua`                                                       | The backend name for computer-use and the `HUMANISH_CUA_LAB_*` error codes                                                                                                                                                                                             | computer use                  |
| `brain`                                                     | The telemetry property: `provider-key`, `local-agent` or `none`                                                                                                                                                                                                        | how the actor gets its model  |
