# Taskly detection benchmark, first run

**2026-09-01, humanish 0.63.0, `openai-computer-use` on hosted E2B desktops, N=3 per arm.**

Six live runs. Both arms use the same persona (`synthetic-new-user`), the same mission, and the
same number of runs. The mission never mentions defects, bugs, or testing; it describes ordinary
use, because a persona told to hunt for bugs will find them whether or not they exist.

## Recall: 15 of 15

| defect | what it is | run 1 | run 2 | run 3 |
|--------|-----------|:-----:|:-----:|:-----:|
| D1 | `Clear completed` does nothing | ✓ | ✓ | ✓ |
| D2 | text over 30 chars silently truncated | ✓ | ✓ | ✓ |
| D3 | `Active` and `Completed` filters swapped | ✓ | ✓ | ✓ |
| D4 | empty list renders the literal text `undefined` | ✓ | ✓ | ✓ |
| D5 | `Save` in edit mode does nothing; only Enter commits | ✓ | ✓ | ✓ |

**5 of 5 in every run.** Each report described what the persona did and what it saw, in the
persona's own words. Verbatim, from three separate runs:

> The filters appeared reversed: **Active** showed the completed "Buy oat milk" task. **Completed**
> showed the two unfinished tasks.

> My longer task, "Call the dentist to arrange a routine check-up for next Thursday afternoon," was
> silently cut down to "Call the dentist to arrange a".

> While renaming, clicking **Save** twice left the task in edit mode. Pressing **Enter** successfully
> saved the new name and exited editing.

## Precision: no invented defects in 3 clean runs

Not one clean run reported any of the five planted defect classes. No run claimed the filters were
reversed, that text was truncated, that Save was dead, that Clear-completed did nothing, or that it
saw `undefined`. Every clean run described the filters and Save working correctly.

What the clean runs did report, all of it true of the app as written:

- `Clear completed` stays visible and enabled when there are no completed tasks (3 of 3 runs)
- `Delete` and `Clear completed` act immediately with no confirmation or undo (1 run)
- the footer count stays global while a filter is applied, which read as inconsistent at first (1 run)

These are design opinions about real behaviour, not false bug reports. A reviewer can act on them
or dismiss them; none is a hallucination.

## What this number is not

Planted defects are more legible, more self-contained, and more reachable than most production
bugs. 15 of 15 is an upper bound on recall in the wild, not a prediction of it. The app is also
small and authored for this purpose, which removes the navigation and state-setup difficulty that
makes real apps hard. Read this as evidence that the loop works end to end and that the persona
reports faithfully. It says nothing yet about defect-finding on an app we did not write.

The honest next step is the same design against a real open-source app at a pinned commit, where
we do not control the surface.

## A defect it found in humanish itself

Clean run 2 exited `HUMANISH_CUA_LAB_FAILED` while its own session read `passed
(goal_satisfied)`. The persona had ended its report with "No functional failures blocked me", and
our self-reported-blocker guard matched the word "blocked" without handling that negation, so a
clean passing run was downgraded to a lab failure. Fixed in this change, with the phrasing pinned
as a regression test.

That is 1 in 6 runs misclassified by our own honesty guard, found only because the benchmark gave
us runs whose correct outcome we knew in advance.
